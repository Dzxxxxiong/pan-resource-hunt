# 输出模板

## 一、`00_docs/alignment.md`（唯一事实来源）

```markdown
# 对齐记录

- 任务名：
- 工作区：
- 阶段 0 状态：已确认

## 任务原话拆解
| 维度 | 解析结果 | 标注 |
|---|---|---|
| 目标物 |  | 明确/模糊/缺失 |
| 交付物 |  |  |
| 约束条件 |  |  |
| 隐含预期 |  |  |

## 目标锁定
（片名、年份、类型、导演、片长、标识 IMDb/豆瓣、上映信息）

## 用户选择
| 问题 | 用户选择 |
|---|---|

## 关键约束与已知风险
1. 网盘链接易被和谐，必须多源冗余。
2. 匿名探测只能判"链接是否存在/提取码是否正确"，**无法验证文件内容与能否转存**。

## 验收判据
- 至少 N 条可判定为"链接存活"的地址
- 每条标注：URL、提取码、自称版本、来源页、发布日、存活判定
- 高画质与枪版分开归类
```

## 二、`00_docs/tasks.md`（任务卡表）

```markdown
| ID | 任务 | 依赖 | 产出物 | 完成判据 |
|---|---|---|---|---|
| T1 | 建立工作区与对齐记录 | — | 00_docs/alignment.md | 文件存在且含确认结论 |
| T2 | 挖源 A（站点/论坛） | T1 | 02_work/raw_a.md | ≥3 条候选链接 |
| T3 | 挖源 B（贴吧/搜索） | T1 | 02_work/raw_b.md | ≥3 条候选链接 |
| T4 | 去重归一化 | T2,T3 | 02_work/seeds.json | 每条含 URL/pwd/来源 |
| T5 | 逐条核验 | T4 | 02_work/verify_final.json | 每条有 status |
| T6 | 生成清单 | T5 | 03_output/资源清单.md | 含可用/失效分组 |
| T7 | 验收自检 | T6 | 03_output/验收报告.md | 逐条对照判据 |

关键路径：T1 → (T2 ∥ T3) → T4 → T5 → T6 → T7
```

## 三、`03_output/资源清单.md`

由 `scripts/hunt.py` 自动生成，结构：

1. 目标影片确认表
2. 已核验可用表（版本 / 提取码 / 分享根目录名实测 / 链接 / 来源 / 发布日）
3. 未取到元数据（**非失效**）
4. 已确认失效
5. 使用方法
6. 备用平台源（超范围附加）
7. 汇总统计 + 画质未验证声明

```markdown
## 遗留风险
| ID | 风险 | 影响 | 已尝试的替代方案 | 建议下一步 |

```

## 五、自检口令

- 「已验证」必须能追到 `errno` 数字。
- 「无法匿名递归子目录」是已知边界，不要写成"核验失败"。
- 发布方的 4K 是**自称**，写进表格时必须带"自称"字样。
